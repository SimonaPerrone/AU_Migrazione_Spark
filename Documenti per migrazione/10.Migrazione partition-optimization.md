# Migrazione Spark 2 -> Spark 3 - partition-optimization

## 1. Descrizione Progetto

### 1.1 A cosa serve questo progetto (spiegato semplice)

`partition-optimization` ottimizza partizioni parquet/Hive in 3 fasi:
1. **repartition** (ottimizzazione),
2. **rollback** (ripristino backup),
3. **delete-backup** (pulizia backup).

### 1.2 Cosa sappiamo oggi dal documento esistente

Il progetto:
- è multi-modulo Maven:
  - `partition-optimization-repartition`
  - `partition-optimization-rollback`
  - `partition-optimization-delete-backup`
- usa Spark `2.4.0.cloudera2`, Scala `2.11.12`,
- ha Driver separati per ciascun modulo.

### 1.3 Significato dei componenti (in parole non tecniche)

- **repartition/Driver.scala**: calcola partizioni ottimali e riscrive dati.
- **rollback/Driver.scala**: ripristina path originali da `_backup`.
- **delete-backup/Driver.scala**: rimuove backup residui.
- **Environment + FunctionUtility**: utility comuni per FS/Hive/log.
- **deploy/**: script operativi (`run_optimize_*`).

### 1.4 Stack tecnico attuale e perché va migrato

Stack attuale:
- Spark 2.4
- Scala 2.11
- Maven multi-modulo

Target:
- Spark 3.x
- Scala 2.12
- revisione semantica DataFrame (`exceptAll`, `mergeSchema`) e script deploy.

## 2. Funzionamento step by step

### Step 1 - Avvio job

Parte il Driver del modulo scelto (repartition/rollback/delete-backup).

### Step 2 - Lettura parametri e config

Legge tabelle target, parametri dimensione ottimale, opzioni integrità.

### Step 3 - Inizializzazione Spark

Crea environment Spark e carica conf runtime.

### Step 4 - Lettura input

Legge partizioni tabella e path fisici in HDFS.

### Step 5 - Pulizia e normalizzazione

Verifica metadati partizioni e schema dati (`mergeSchema` dove necessario).

### Step 6 - Regole di business (flow)

- Repartition: calcolo numero partizioni ottimale e riscrittura.
- Rollback: move backup -> path originale.
- Delete backup: cancellazione `_backup`.

### Step 7 - Costruzione dataset finale

Genera output fisico ottimizzato o stato ripristinato.

### Step 8 - Scrittura output

Scrive parquet e script di riparazione metadata (`msck_repair_table.sh`).

### Step 9 - Chiusura e logging

Log per ogni tabella/partizione con esito operazione.

## 3. Modifiche da apportare per componente (guida pratica per principiante)

## 3.1 `pom.xml` root + moduli - cosa cambiare, dove, e perché

### Obiettivo

Portare tutti i moduli a Spark 3 + Scala 2.12.

### Checklist operativa

1. Aggiornare versioni Spark/Scala nel root.
2. Aggiornare artifact `_2.12`.
3. Verificare pom modulo (repartition/rollback/delete-backup).
4. Correggere eventuali riferimenti legacy (es. path root build non coerenti).

### Errori tipici da principiante

- lasciare configurazioni root incoerenti con i moduli;
- migrare un modulo e non gli altri due.

---

## 3.2 Codice Scala (3 Driver + utility) - cosa controllare concretamente

### Obiettivo

Garantire che ottimizzazione/rollback/pulizia funzionino invariati su Spark 3.

### Dove intervenire prima

1. `partition-optimization-repartition/Driver.scala`
2. `partition-optimization-rollback/Driver.scala`
3. `partition-optimization-delete-backup/Driver.scala`

### Cosa cambiare (pratico)

- validare `exceptAll`, `mergeSchema`, count integrità,
- verificare move/delete su FS in ambiente target,
- controllare semantica SQL su metadati tabella.

### Config transitoria utile

- solo se necessario, flag SQL legacy temporanei.

### Errori tipici da principiante

- non testare rollback e delete-backup dopo repartition;
- non validare l’integrità record pre/post ottimizzazione.

---

## 3.3 Configurazione runtime (properties + script)

### Obiettivo

Mantenere il flusso operativo completo dei tre script.

### Cosa verificare

1. `run_optimize_partition.sh`
2. `run_optimize_rollback.sh`
3. `run_optimize_delete_backup.sh`
4. `params.properties` e script `msck_repair_table.sh`.

### Errori tipici da principiante

- script aggiornati a metà;
- mismatch path backup e path tabella.

---

## 3.4 Ordine consigliato di migrazione (molto pratico)

1. Migra pom root e moduli.
2. Valida modulo repartition.
3. Valida rollback su caso controllato.
4. Valida delete-backup.
5. Esegui ciclo completo su tabella test.

## 5. Glossario minimo (per orientarti subito)

- **Repartition**: ridistribuzione dei dati in un numero ottimale di partizioni.
- **Rollback**: ripristino allo stato precedente.
- **Backup path**: copia dati usata per sicurezza.
- **MSCK REPAIR TABLE**: riallineamento metadati partizioni Hive.
