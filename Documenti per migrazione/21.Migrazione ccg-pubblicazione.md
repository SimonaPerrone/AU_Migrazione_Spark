# 21.Migrazioneccg-pubblicazione.md

## 1) Descrizione Progetto

### 1.1 Obiettivo e perimetro
Il progetto `ccg-pubblicazione` esegue la pubblicazione dei risultati CCG per diverse sessioni business (`AGG`, `SBG`, `CDP_FIN`, `CDP_RIC`), partendo da import dati preliminari e con export finale di esito.

### 1.2 Stack tecnologico attuale
- Spark `2.4.0.cloudera2`
- Scala `2.11.12`
- Java `8`
- Build Maven (jar shaded + deploy resources)
- Parsing argomenti con `scopt`
- Configurazioni via `config.properties` filtrato per profilo (`prod/dev/coll`)

### 1.3 Architettura logica
- **Entrypoint:** `src/main/scala/it/eng/au/ccgPubblicazione/Driver.scala`
- **Routing sessione:** `Driver` seleziona session factory in base a `-s`:
  - `AggSession`
  - `SbgSession`
  - `CdpFinSession`
  - `CdpRicSession`
- **Orchestrazione deploy:**
  - `src/main/resources/deploy/run_ccg.sh` (import sqoop + invocazione sessioni + export esito)
  - `src/main/resources/deploy/run_ccg_specific_session.sh` (spark-submit del job)

### 1.4 Punti sensibili per Spark 3
- Compatibilità Spark/Scala (passaggio 2.11 → 2.12 tipicamente necessario con Spark 3).
- Possibili differenze SQL/date/null semantics nelle trasformazioni interne alle sessioni.
- Adeguamento script da `spark2-submit` a `spark-submit`.

## 2) Funzionamento step by step

1. `run_ccg.sh` acquisisce parametri (`-e data`, `-s flowTypeName`, `-t tipo`).
2. Esegue import Sqoop (richiesta PDR/filtro) in base a `TIPO`.
3. Se import ok, invoca `run_ccg_specific_session.sh` per ogni sessione richiesta.
4. Lo script lancia `it.eng.au.ccgPubblicazione.Driver` con parametri business.
5. `Driver` fa parsing argomenti e instrada alla sessione corretta (`AGG/SBG/CDP_FIN/CDP_RIC`).
6. Sessione esegue pipeline di pubblicazione e produce output.
7. A fine sessione viene eseguito export esiti (`sqoop-export-esito.sh`).

## 3) Modifiche da apportare ad ogni singola componente

### 3.1 `pom.xml`
- Aggiornare:
  - `spark-core`, `spark-sql`, `spark-hive` → Spark 3 target.
  - `scala.version` / `scala.compat.version` coerenti con Spark 3.
- Aggiornare librerie di test (Scalatest) a versioni compatibili Scala target.
- Verificare plugin `scala-maven-plugin`, `shade`, `surefire` su toolchain aggiornata.

### 3.2 Codice applicativo
- Verificare tutte le sessioni (`AggSession`, `SbgSession`, `CdpFinSession`, `CdpRicSession`) su:
  - cast impliciti e encoder,
  - join e null-handling,
  - parsing date/timestamp.
- Se presenti query SQL testuali: adeguare a regole Spark 3 (ansi/time parser).

### 3.3 Script e deploy
- `run_ccg.sh`, `run_ccg_specific_session.sh`:
  - sostituire `spark2-submit` con `spark-submit`,
  - riallineare conf Spark 3 (`AQE`, shuffle, dynamic allocation).
- Validare template config profili (`prod/dev/coll`) e percorsi deploy.

### 3.4 Integrazioni esterne
- Validare catena end-to-end Sqoop import/export.
- Verificare formato/partizionamento output atteso dai consumer downstream.
