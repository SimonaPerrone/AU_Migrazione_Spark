# ee_aggregato_cloudera — Migrazione Spark 1.6 -> Spark 3

## 1. Descrizione Progetto
- **Tipo:** grande suite Spark Scala multi-comando (`FlussoMisureTool`).
- **Entry point:** `it.au.misure.cli.FlussoMisureTool`
- **Stack attuale:** Spark `1.6.0-cdh5.12.1`, Scala `2.10.5`, Java 8.
- **Nota:** migrazione più complessa (major jump).

## 2. Funzionamento step by step
1. CLI parse (`CommandLineOptions`) decide comando operativo.
2. Esegue moduli ingestion/decompressione/aggregazione/SEM/portale.
3. Moduli principali:
   - `ingestione/*` (Injection, Decomprime, CheckAmmissibilita)
   - `aggregazioni/*` (orarie, AM)
   - `commit/*`, `sem/*`, `portale/*`
4. Uso esteso di config profili (`dev/prod/test`) e deploy assets (`deploy/*`, XSD, hive scripts).

## 3. Modifiche da apportare
### 3.1 Build (obbligatoria)
- `pom.xml`: Spark 3.5.x, Scala 2.12.x.
- Rimuovere artifact legacy Spark 1.6 (`spark-assembly_2.10`, dipendenze obsolete).
- Riallineare test libs/scala plugin/surefire.

### 3.2 Codice
- Migrare API Spark 1.x -> Spark 3 (`SparkSession`, SQL behavior, parser datetime).
- Verificare moduli ingestion/aggregazioni più critici (molto codice legacy).
- Rivedere eventuali incompatibilità in UDF, join, cast, null semantics.

### 3.3 Config/script
- `spark-defaults.conf` e script deploy: rimuovere impostazioni CDH obsolete.
- Allineare profili `src/main/resources/profiles/*/config.properties`.

## 4. Test da prevedere
- Priorità alta su test esistenti (`FlussoMisureToolTest`, test ammissibilità/utility).
- E2E per almeno 3 comandi chiave: ingestion, aggregazione oraria, aggregazione AM.
- Confronto output legacy vs Spark3 su KPI e tabelle finali.
