# 31.Migrazioneportale-consumi-2.0.md

## 1) Descrizione Progetto

### 1.1 Obiettivo e perimetro
Il progetto `portale-consumi-2.0` alimenta il dominio Portale Consumi Gas con due macro-flussi:
- `FORNITURE_GAS`
- `MISURE_GAS` (con gestione intervalli tipo `3M`, `33M`, `FULL`)

### 1.2 Stack tecnologico attuale
- Spark `2.4.0.cloudera2`
- Scala `2.11.12`
- Java `8`
- Maven + shade
- Integrazione Mongo (`mongo-spark-connector_2.11:2.4.3`, `mongo-scala-driver_2.11:4.11.0`)

### 1.3 Architettura logica
- **Entrypoint:** `src/main/scala/it/eng/au/portaleConsumi/Driver.scala`
- Routing flow:
  - `FornitureGasFlow`
  - `MisureGasFlow`
- Script deploy principali:
  - `run_gas_forniture_portale_consumi.sh`
  - `run_gas_misure_3m_portale_consumi.sh`
  - `run_gas_misure_33m_portale_consumi.sh`
  - `run_gas_misure_full_portale_consumi.sh`
  - `run_gas_forniture_misure_full_portale_consumi.sh`
  - `run_gas_forniture_misure_full_forzato_portale_consumi.sh`
  - `run_gas_portale_consumi_schedule.sh` (lancio condizionato primo lunedì del mese)

### 1.4 Punti sensibili per Spark 3
- Compatibilità con connettore Mongo su Spark 3.
- Coerenza tra modalità standard/full/forzato.
- Aggiornamento script da `spark2-submit` a `spark-submit`.

## 2) Funzionamento step by step

1. Uno script deploy avvia `it.eng.au.portaleConsumi.Driver` con `-f` (flow) e properties.
2. `Driver` fa parse argomenti (`ArgsFactory`), inizializza environment e SparkSession.
3. In base al flow esegue `FornitureGasFlow` o `MisureGasFlow`.
4. Negli script combinati viene lanciata prima FORNITURE, poi MISURE, poi refresh metadati Impala.
5. Lo scheduler mensile sceglie run standard o forzata in base al calendario.
