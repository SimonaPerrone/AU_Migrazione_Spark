# 27.Migrazionecdp-codprofstd-tds.md

## 1) Descrizione Progetto

### 1.1 Obiettivo e perimetro
`cdp-codprofstd-tds` esegue il ricalcolo del codice profilo standard a partire da nuova TDS, con pipeline batch Spark e output su tabelle di destinazione.

### 1.2 Stack tecnologico attuale
- Spark `2.4.0.cloudera2`
- Scala `2.11.12`
- Java `8`
- Maven + shade
- Entrypoint `it.eng.cdp_codprofstd_tds.Driver`

### 1.3 Architettura logica
- `Driver.scala`:
  - parse args (`FlowArgsFactory`)
  - init environment e logging
  - esegue `TdsCodProfStd.run()`
- Script deploy: `src/main/resources/deploy/codprofstd-submit.sh`
- Test presenti (`EnvironmentSparkTest` + test controller).

### 1.4 Punti sensibili per Spark 3
- Nel `pom.xml` è presente dipendenza legacy `spark-csv_2.10` e `scopt_${scala.minor.version}` con minor `2.10`: punto critico da correggere.
- Verifica semantica SQL/date sui ricalcoli TDS.

## 2) Funzionamento step by step

1. Lo script invoca `Driver` con path properties.
2. `Driver` inizializza Spark context e proprietà di run.
3. Viene avviato il controller `TdsCodProfStd`.
4. Pipeline ricalcola codici profilo e scrive output.

## 3) Modifiche da apportare ad ogni singola componente

### 3.1 `pom.xml`
- Aggiornare Spark 2 → Spark 3.
- Aggiornare Scala compatibile Spark 3.
- Rimuovere/sostituire dipendenze legacy (`spark-csv_2.10`, `scopt_2.10`) con alternative compatibili.
- Verificare test framework e plugin build.

### 3.2 Codice applicativo
- Validare compatibilità controller/DAO con Spark 3.
- Verificare parser date e cast schema.

### 3.3 Script deploy
- Migrare `spark2-submit` a `spark-submit`.
- Aggiornare conf runtime (shuffle, memory overhead).
