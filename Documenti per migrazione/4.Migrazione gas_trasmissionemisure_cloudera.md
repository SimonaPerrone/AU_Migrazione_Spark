# gas_trasmissionemisure_cloudera — Migrazione Spark 2 -> Spark 3

## 1. Descrizione Progetto
- **Tipo:** PySpark (script-based), con moduli `pyspark2/` (`Main.py`, `Ingestion.py`) + script SQL/SH.
- **Entry point:** `source/pyspark2/Main.py`
- **Stack attuale rilevato:** uso `SparkContext`, `SQLContext`, `HiveContext` (pattern legacy Spark 1/2), orchestrazione flussi A01/A40/D01/SM1 (`selectorFlusso.py`).

## 2. Funzionamento step by step
1. `Main.py` legge parametri CLI (flusso, data, query/query_file, mode).
2. `Ingestion.start()` crea context Spark, legge query Hive, recupera lista file XML.
3. Validazioni nome file + XSD, parsing XML per tipo flusso.
4. Generazione record dettaglio e record principali.
5. Scrittura su parquet partizionato + `MSCK REPAIR TABLE`.

## 3. Modifiche da apportare
### 3.1 Componenti
- `source/pyspark2/Ingestion.py`: migrare da `SparkContext/SQLContext/HiveContext` a `SparkSession`.
- `source/pyspark2/Main.py`, `Params.py`, `selectorFlusso.py`: mantenere logica, adeguare bootstrap Spark 3.
- `source/conf/*.json`, `log4j.properties`: riallineare conf runtime Spark 3.
- Script shell/SQL (`source/bin/script/ca/*`, `source/bin/bonifica/*`): verificare compatibilità SQL/Hive con Spark 3.

### 3.2 Rischi tecnici principali
- API legacy (`HiveContext`) e parsing XML custom.
- Uso di path/parquet/hive command in stile CDH.
- Presenza di file `.pyc` nel repo (da escludere da build/deploy).

## 4. Test da prevedere
- Unit su parsing parametri/selector flusso.
- Integration su almeno un flusso reale (A01 e SM1).
- Confronto output Spark2 vs Spark3 su:
  - numero file validi/scartati
  - righe dettaglio
  - partizioni e contenuto tabella finale.
