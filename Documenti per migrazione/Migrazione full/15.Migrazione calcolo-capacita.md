# MIGRAZIONE_SPARK3_CALCOLO_CAPACITA

## 1. Descrizione Progetto

### 1.1 Obiettivo e contesto
`calcolo-capacita` è un progetto legacy critico con migrazione **major**: Spark 1.6 / Scala 2.10 verso Spark 3.  
Implementa calcolo capacità tramite flow principale `CalcoloCtcFlow`, con forte dipendenza da API Spark/Hive legacy.

### 1.2 Perimetro funzionale e tecnico
- Entrypoint `it.au.misure.calcolo_capacita.Main`.
- Inizializzazione contesti in `SparkImplicit` (SQLContext/HiveContext).
- Elaborazione nel flow `CalcoloCtcFlow`.
- Ecosistema deploy ricco: script import/export/refresh/spark-submit.

### 1.3 Architettura logica
1. Parsing args runtime (`data_calc`, `x`, `y`, `automatic`, `verbose`).
2. Caricamento dataset anagrafica/perimetro/misure.
3. Trasformazioni e calcoli per path di business.
4. Scrittura finale su Hive.
5. Orchestrazione con script shell/Python in `src/main/resources/deploy`.

### 1.4 Tecnologie e dipendenze principali (stato attuale)
- Spark 1.6.0-cdh5.12.1
- Scala 2.10.5
- API legacy `SparkContext`, `SQLContext`, `HiveContext`
- Dipendenze storiche: `spark-assembly`, `spark-csv`, `spark-xml`
- Test Scala (scalatest/scalamock) + suite estese

---

## 2. Funzionamento step by step del progetto

1. Script `gas-calcolo-capacita-spark-submit.sh` invoca il job con parametri runtime.
2. `Main` crea execution id e costruisce il flow.
3. `SparkImplicit` inizializza i contesti Spark/Hive legacy.
4. `CalcoloCtcFlow` legge i dataset di input da DAO/Hive.
5. Esegue preparation, join, filtri e calcoli formula per path.
6. Applica cache/azioni tecniche e configurazioni shuffle.
7. Unisce i risultati e costruisce dataset finale.
8. Scrive output in tabella Hive (`insertInto` in overwrite).
9. Script di contorno gestiscono import, refresh, export e integrazione operativa.

## 3. Modifiche da apportare ad ogni singola componente del progetto

### 3.1 `pom.xml` (intervento principale)
1. Migrare Scala 2.10 -> 2.12 (allineata alla Spark 3 target).
2. Migrare Spark 1.6 -> Spark 3.x (`spark-core/spark-sql/spark-hive` coerenti con cluster).
3. Rimuovere dipendenze obsolete/non più necessarie (`spark-assembly`, `spark-csv` legacy).
4. Aggiornare plugin build/test (scala-maven-plugin, surefire, shade).
5. Rivalutare dipendenze test (scalamock/scalatest) su nuove versioni Scala.

### 3.2 Codice Scala (`src/main/scala`)
1. Sostituire pattern `SQLContext/HiveContext` con `SparkSession`.
2. Adeguare API Spark SQL/DataFrame non più compatibili.
3. Verificare semantica SQL Spark 3 (date/cast/null/ANSI).
4. Verificare funzioni deprecate (es. `unionAll` -> `union` dove necessario).
5. Riesaminare parser argomenti e gestione errori (`System.exit`) per robustezza operativa.

### 3.3 Script e orchestrazione (`src/main/resources/deploy`)
1. Aggiornare `gas-calcolo-capacita-spark-submit.sh` a conf Spark 3 runtime cluster.
2. Verificare script import/export/refresh (shell/python) e dipendenze ambientali.

## 5. Glossario minimo
- **Migrazione major**: cambio di major version con incompatibilità API/semantica.
- **SparkSession**: entrypoint unificato Spark 2+/3.
- **Flow**: pipeline di trasformazioni dati orchestrata in sequenza.
