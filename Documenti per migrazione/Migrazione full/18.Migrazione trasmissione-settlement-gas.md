# MIGRAZIONE_SPARK3_TRASMISSIONE_SETTLEMENT_GAS

## 1. Descrizione Progetto

### 1.1 Obiettivo e contesto
`trasmissione-settlement-gas` è un progetto multi-modulo per il processo settlement gas:
- modulo **ammissibilita**
- modulo **calcolo**
- modulo **common**

Il processo combina controlli di qualità/ammissibilità file e calcoli finali su dataset settlement.

### 1.2 Perimetro funzionale e tecnico
- `ammissibilita`: validazione file/record (TFC, VPG, QKRIUD), report ammissibilità, pubblicazione esiti.
- `calcolo`: calcolo profili e scritture finali su tabelle target.
- `common`: componenti condivisi (schema/utility/environment comuni).

### 1.3 Architettura logica
- **Parent Maven** con packaging `pom` e moduli.
- **Entrypoint ammissibilita**: `it.eng.au.ammissibilitaSettlementGas.Driver`
- **Entrypoint calcolo**: `it.eng.au.calcoloSettlementGas.Driver`
- **Deploy script**:
  - `run-ammissibilita.sh`
  - `run-calcolo.sh`
- **Test**: presenti in entrambi i moduli (`controller`, `utility`).

### 1.4 Stack tecnologico attuale
- Spark `2.4.0.cloudera2`
- Scala `2.11.12`
- Java 8
- Maven multi-modulo
- Dipendenze Spark/Hive + `scopt`, `kryo-serializers`

---

## 2. Funzionamento step by step del progetto

1. Viene lanciato il modulo `ammissibilita` (script o submit diretto).
2. Il driver legge parametri e inizializza environment.
3. Vengono processati i file TFC/VPG/QKRIUD:
   - controlli file-level
   - controlli record-level
   - gestione già trasmessi/già computati
4. Vengono prodotti report di ammissibilità e scritture su tabelle intermedie/finali.
5. Viene lanciato il modulo `calcolo`.
6. Il driver `calcolo` legge i dataset validati, applica logiche di calcolo profili e persiste output.
7. Le tabelle finali vengono aggiornate (inclusi passaggi su tabelle backup/ATG dove previsto).

### 3.1 Parent `pom.xml`
1. Upgrade Spark 2.4 -> Spark 3.x.
2. Upgrade Scala 2.11 -> 2.12.
3. Verifica allineamento versioni tra moduli (`ammissibilita`, `calcolo`, `common`).

### 3.2 Modulo `ammissibilita`
1. Verificare compatibilità controlli CSV/record con Spark 3.
2. Verificare operazioni su DataFrame/RDD e persist/unpersist.
3. Validare logiche di deduplica, join e scrittura report in Spark 3.

### 3.3 Modulo `calcolo`
1. Verifica logica calcolo su profili e partizioni (annomese).
2. Verificare semantica SQL Spark 3 (date/null/cast/ansi).
3. Validare scritture finali e passaggi backup/restore di partizione.

### 3.4 Modulo `common` e deploy
1. Aggiornare utility comuni per eventuali API Spark deprecate.
2. Aggiornare `run-ammissibilita.sh` / `run-calcolo.sh` per runtime Spark 3.
3. Tarare parametri risorse (executor/driver/dynamic allocation).
