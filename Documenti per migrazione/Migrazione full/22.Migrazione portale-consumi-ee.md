# 22.Migrazioneportale-consumi-ee.md

## 1) Descrizione Progetto

### 1.1 Obiettivo e perimetro
`portale-consumi-ee` è un progetto **multi-modulo** per alimentare funzioni portale consumi elettrico:
- `calcolo_forniture`
- `export_misure`
- `storico_misure_ee`
- `common` (librerie condivise e packaging deploy)

### 1.2 Stack tecnologico attuale
- Spark `2.4.0.cloudera2`
- Scala `2.11.12`
- Java `8`
- Maven parent + moduli
- `export_misure` usa Mongo connector legacy (`mongo-spark-connector_2.11:2.4.3`)

### 1.3 Architettura logica
- **Parent:** `portale-consumi-ee/pom.xml` (`packaging: pom`)
- **Modulo calcolo forniture:** entrypoint `calcolo_forniture/.../Main.scala`
- **Modulo export misure:** entrypoint `export_misure/.../Main.scala`
- **Modulo storico misure:** entrypoint `storico_misure_ee/.../Main.scala`
- **Modulo common:** utility condivise + assemblaggio deploy cross-modulo.

### 1.4 Punti sensibili per Spark 3
- Multi-modulo: tutte le versioni devono restare coerenti.
- Mongo connector 2.x non è la scelta standard per Spark 3 moderni: possibile refactor API.
- Script di avvio attualmente su `spark2-submit`.

## 2) Funzionamento step by step

1. Build parent Maven compila `common` e moduli applicativi.
2. `calcolo_forniture/Main.scala` esegue in sequenza i flow `fornitura_ele_*` e produce dataset di forniture.
3. `export_misure/Main.scala` fa parsing args (`flow`, `storico`) e seleziona il percorso:
   - export 3M / 33M
   - initialization 3M / 33M
4. `storico_misure_ee/Main.scala` esegue calcolo storico 3M o 33M in base ai parametri.
5. Script deploy dedicati lanciano i singoli jar modulo:
   - `spark-submit-calcolo-forniture.sh`
   - `spark-submit-export-misure.sh`
   - `spark-submit-misure-storico.sh`
6. `common` raccoglie artefatti in una struttura deploy unica.

## 3) Modifiche da apportare ad ogni singola componente

### 3.1 `portale-consumi-ee/pom.xml` (parent)
- Aggiornare Spark/Scala a target Spark 3.
- Centralizzare `dependencyManagement` coerente per tutti i moduli.
- Verificare plugin Maven/Scala su Java target.

### 3.2 `common/pom.xml` e librerie condivise
- Adeguare dipendenze condivise (Spark/Scala/config/scopt).
- Validare packaging deploy cross-modulo post-migrazione.

### 3.3 `calcolo_forniture/pom.xml` + `Main.scala`
- Allineare dipendenze ereditate al parent aggiornato.
- Verificare compatibilità trasformazioni e write/read con Spark 3.
- Aggiornare script `spark-submit-calcolo-forniture.sh`.

### 3.4 `export_misure/pom.xml` + `Main.scala`
- Punto critico: migrare integrazione Mongo a versione/API compatibile Spark 3.
- Verificare flussi `flowFull/flowInitialization` e ramo `storico`.
- Aggiornare script `spark-submit-export-misure.sh`.

### 3.5 `storico_misure_ee/pom.xml` + `Main.scala`
- Aggiornare stack e verificare logica `storico` (3M/33M).
- Aggiornare script `spark-submit-misure-storico.sh`.

### 3.6 Configurazioni e deploy
- Allineare profili (`dev/prod`) e parametri runtime Spark 3.
- Uniformare `spark2-submit` → `spark-submit` su tutti gli script.

## 4) Test da prevedere

### 4.1 Unit test
- Modulo `common`: `EnvironmentSparkTest`, utility test.
- Modulo `calcolo_forniture`: `EnvironmentSparkTest` + test flow.
- Moduli `export_misure` e `storico_misure_ee`: `EnvironmentSparkTest` + test per stage/storico.

### 4.2 Integration test
- Pipeline completa per ogni modulo con dati realistici.
- Test end-to-end con dipendenze inter-modulo e output deploy unificato.

### 4.3 Regression test
- Confronto output Spark 2 vs Spark 3 (fasi 3M/33M e calcolo forniture).
- Verifica coerenza record e KPI principali.

### 4.4 Performance test
- Benchmark per modulo (soprattutto `export_misure` e `storico_misure_ee`).
- Tuning partizioni, AQE, memory overhead.
