# Migrazione Spark 2 -> Spark 3 - delete-old-partition

## 1. Descrizione Progetto

### 1.1 A cosa serve questo progetto (spiegato semplice)

`delete-old-partition` è un job batch Scala/Spark che elimina partizioni vecchie da tabelle Hive e pulisce i path HDFS corrispondenti.

In pratica:
1. legge l’elenco tabelle,
2. calcola quali partizioni tenere/eliminare,
3. esegue `ALTER TABLE DROP PARTITION`,
4. cancella i dati fisici su filesystem.

### 1.2 Cosa sappiamo oggi dal documento esistente

Il progetto:
- usa Spark `2.4.0.cloudera2` e Scala `2.11.12`,
- ha entrypoint `it.eng.au.deleteOldPartition.Driver`,
- legge retention/config da properties e script deploy.

### 1.3 Significato dei componenti (in parole non tecniche)

- **`Driver.scala`**: orchestration completa della procedura.
- **`utility/environment`**: crea/espone contesto Spark e proprietà runtime.
- **`deploy/run_delete_old_partition.sh`**: script di avvio operativo.
- **`profiles/*/config.properties`**: configurazioni ambiente.

### 1.4 Stack tecnico attuale e perché va migrato

Stack attuale:
- Spark: `2.4.0.cloudera2`
- Scala: `2.11.12`
- Java: `1.8`
- Build: Maven

Target:
- Spark 3.x
- Scala 2.12.x
- runtime Spark moderno e configurazioni allineate.

## 2. Funzionamento step by step

### Step 1 - Avvio job

Parte `Driver.main(args)`.

### Step 2 - Lettura parametri e config

Legge properties e inizializza `Environment`.

### Step 3 - Inizializzazione Spark

Crea il contesto Spark applicativo.

### Step 4 - Lettura input

Legge lista tabelle (`tables`) e partizioni (`SHOW PARTITIONS`).

### Step 5 - Pulizia e normalizzazione

Filtra partizioni CCG e ordina per decidere quali eliminare.

### Step 6 - Regole di business (flow)

Calcola retention: quante partizioni mantenere e quali cancellare.

### Step 7 - Costruzione dataset finale

Costruisce l’elenco finale partizioni da eliminare.

### Step 8 - Scrittura output

Esegue `ALTER TABLE ... DROP PARTITION` e delete path HDFS.

### Step 9 - Chiusura e logging

Registra log per tabella/partizione ed esito finale.

## 3. Modifiche da apportare per componente (guida pratica per principiante)

## 3.1 `pom.xml` - cosa cambiare, dove, e perché

### Obiettivo

Portare build e dipendenze a Spark 3 + Scala 2.12.

### Checklist operativa

1. `spark.version` -> `3.5.x`
2. `scala.version` -> `2.12.x`
3. `scala.compat.version` -> `2.12`
4. Artifact Spark `_2.12` (`core/sql/hive`)
5. Aggiornare librerie test/plugin Maven compatibili.

### Errori tipici da principiante

- lasciare artifact `_2.11`,
- aggiornare Spark senza aggiornare Scala,
- ignorare dipendenze transitive obsolete.

---

## 3.2 Codice Scala (`Driver`, `Environment`) - cosa controllare concretamente

### Obiettivo

Rendere compatibili query metadata Hive e logica partition cleanup.

### Dove intervenire prima

1. `Driver.scala`
2. `utility/environment/*`
3. helper che leggono proprietà/FS

### Cosa cambiare (pratico)

- verificare compatibilità `SHOW PARTITIONS` / `DESC FORMATTED`,
- controllare semantica e parsing partizioni,
- verificare API SparkSession usate da `Environment`.

### Config transitoria utile

- eventuali `spark.sql.legacy.*` solo se necessari in fase ponte.

### Errori tipici da principiante

- non testare query metadata su Spark 3,
- cancellazioni path senza verifica robusta partizioni.

---

## 3.3 Configurazione runtime (properties + spark-submit)

### Obiettivo

Mantenere comportamento operativo identico in cluster Spark 3.

### Cosa verificare

1. `run_delete_old_partition.sh`
2. `deploy/params.properties`
3. `profiles/*/config.properties`
4. conf Spark SQL e permessi filesystem.

### Errori tipici da principiante

- script submit non allineato a Spark 3,
- parametri retention non caricati correttamente.

## 5. Glossario minimo (per orientarti subito)

- **Retention**: numero di partizioni da mantenere.
- **Partition pruning**: gestione subset partizioni.
- **Hive Metastore**: catalogo metadata tabelle/partizioni.
- **Idempotenza**: run ripetute senza effetti indesiderati.
