# Migrazione Spark 2 -> Spark 3 - scambio-dati-gasivori

## 1. Descrizione Progetto

### 1.1 A cosa serve questo progetto (spiegato semplice)

`scambio-dati-gasivori` è un job Spark batch che elabora e pubblica dati gasivori tramite una lista di aggregatori, con supporto a script deploy/sqoop.

### 1.2 Cosa sappiamo oggi dal documento esistente

Il progetto:
- usa Spark `2.4.0.cloudera2`, Scala `2.11.12`,
- ha entrypoint `it.eng.au.scambioDatiGasivori.Driver`,
- usa `ArgsFactory`, `AggregatorFactory`, `Environment`,
- ha script `run-pubblicazione-dati-gasivori.sh` e `spark-submit-*`.

### 1.3 Significato dei componenti (in parole non tecniche)

- **Driver.scala**: avvia il processo e lancia tutti gli aggregatori.
- **args**: legge parametri run/properties.
- **factory**: costruisce l’elenco aggregatori da eseguire.
- **controller/dao/schema**: logica business e accesso dati.
- **deploy/**: run script, spark-submit, sqoop, parametri.

### 1.4 Stack tecnico attuale e perché va migrato

Stack attuale:
- Spark 2.4
- Scala 2.11
- Maven

Target:
- Spark 3.x
- Scala 2.12
- allineamento script submit e compatibilità SQL Spark 3.

## 2. Funzionamento step by step

### Step 1 - Avvio job

Parte `Driver.main(args)`.

### Step 2 - Lettura parametri e config

`ArgsFactory.parse` legge proprietà e modalità output.

### Step 3 - Inizializzazione Spark

`Environment.getOrCreate(...)` crea contesto Spark e imposta proprietà runtime.

### Step 4 - Lettura input

Gli aggregatori leggono input tramite DAO specifici.

### Step 5 - Pulizia e normalizzazione

Ogni aggregatore prepara i dati necessari alle proprie trasformazioni.

### Step 6 - Regole di business (flow)

`AggregatorFactory.getAggregators` costruisce la lista; il Driver esegue `agg.run()` su ciascun aggregatore.

### Step 7 - Costruzione dataset finale

Gli aggregatori producono dataset/output per la pubblicazione.

### Step 8 - Scrittura output

Scrittura output e passaggi deploy/sqoop previsti.

### Step 9 - Chiusura e logging

Log iniziale/finale tramite `LogUtility` e log per aggregatore.

## 3. Modifiche da apportare per componente (guida pratica per principiante)

## 3.1 `pom.xml` - cosa cambiare, dove, e perché

### Obiettivo

Allineare dipendenze build a Spark 3 + Scala 2.12.

### Checklist operativa

1. aggiornare `spark.version` a 3.5.x
2. aggiornare Scala a 2.12.x
3. aggiornare artifact Spark `_2.12`
4. aggiornare librerie test/plugin.

### Errori tipici da principiante

- dipendenze Spark aggiornate ma `scala.compat.version` vecchia;
- plugin test non compatibili.

---

## 3.2 Codice Scala (Driver/factory/aggregatori) - cosa controllare concretamente

### Obiettivo

Preservare la sequenza aggregatori e l’output business.

### Dove intervenire prima

1. `Driver.scala`
2. `AggregatorFactory`
3. aggregatori principali e DAO associati.

### Cosa cambiare (pratico)

- verificare compatibilità API DataFrame/SQL Spark 3,
- gestire cast/date/null in modo esplicito,
- controllare eventuali differenze in join/aggregazioni.

### Config transitoria utile

- flag `spark.sql.legacy.*` solo dove indispensabili.

### Errori tipici da principiante

- testare solo un aggregatore e non la catena completa;
- non confrontare output per modalità diverse (`output.file.modes`).

---

## 3.3 Configurazione runtime (properties + spark-submit)

### Obiettivo

Esecuzione stabile degli script operativi su Spark 3.

### Cosa verificare

1. `run-pubblicazione-dati-gasivori.sh`
2. `spark-submit-pubblicazione-dati-gasivori.sh`
3. `params.properties`, `deploy/hive`, `deploy/sqoop`
4. profili `prod/test`.

### Errori tipici da principiante

- script submit non aggiornato alle nuove conf cluster;
- differenze profilo non gestite (prod/test).

---

## 3.4 Ordine consigliato di migrazione (molto pratico)

1. Aggiorna pom.
2. Porta compilazione in verde.
3. Verifica Driver + AggregatorFactory.
4. Migra/valida aggregatori principali.
5. Aggiorna deploy script.
6. Esegui test end-to-end.

## 4. Test da prevedere (spiegati per chi parte da zero)

## 4.1 Unit test - test piccoli e veloci

- parsing args/properties,
- test utility environment,
- test componenti aggregatori isolati.

## 4.2 Integration test - test end-to-end

- esecuzione completa pipeline aggregatori,
- confronto Spark2/Spark3 su count, KPI, schema.

## 4.3 Test non funzionali

- performance complessiva e per aggregatore,
- stabilità su run consecutivi.

## 4.4 Criteri di accettazione finali

1. Output coerente col legacy
2. Nessun errore runtime Spark 3
3. Script deploy/sqoop funzionanti.

## 5. Glossario minimo (per orientarti subito)

- **Aggregator**: componente che applica un blocco di elaborazione business.
- **Factory**: componente che costruisce oggetti/flow da eseguire.
- **Profilo**: set di configurazioni per ambiente (prod/test).
- **KPI**: metriche chiave usate per confrontare output.
