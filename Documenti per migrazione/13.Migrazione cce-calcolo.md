# MIGRAZIONE_SPARK3_CCE_CALCOLO

## 1. Descrizione Progetto

### 1.1 Obiettivo e contesto
Il progetto `cce-calcolo` implementa il calcolo CCE su più processi/famiglie di flusso (P/PR/PEIN/PREIN), con logiche di ammissibilità, annullamento e calcolo finale.  
È un job Spark batch su cluster Cloudera, con packaging Maven e deploy via script shell.

### 1.2 Perimetro funzionale e tecnico
- Input da tabelle Hive/area dati CCE.
- Elaborazioni tramite controller/DAO specializzati.
- Produzione output calcolato e tracciamento esecuzione.
- Avvio tramite `run_cce.sh` con parametri business e parametri runtime Spark.

### 1.3 Architettura logica
- **Entrypoint**: `it.eng.au.cceCalcolo.Driver`.
- **Layer applicativi**:
  1. parsing argomenti (`ArgsFactory`, `CalcoloArgs`);
  2. controller (ammissibilità/annullamento/calcolo);
  3. DAO di lettura/scrittura;
  4. utility e configurazioni.
- **Deploy**: `src/main/resources/deploy` (`run_cce.sh`, `log4j.properties`, `conf`).

### 1.4 Tecnologie e dipendenze principali
- Java 8
- Scala 2.11.12
- Spark 2.4.0 Cloudera (`spark-core/spark-sql/spark-hive`)
- Maven + scala-maven-plugin + shade
- Scalatest + JUnit

---

## 2. Funzionamento step by step del progetto

1. Lo script `run_cce.sh` prepara parametri business (`-a`, `-m`, `-t`, `-f`) e risorse Spark.
2. Viene lanciato `spark2-submit` con classe main `it.eng.au.cceCalcolo.Driver`.
3. Il `Driver` esegue parsing/validazione argomenti.
4. Viene inizializzato il contesto Spark/Hive e caricata la configurazione.
5. Si eseguono i controlli di ammissibilità sui dataset necessari.
6. Si applicano le logiche di annullamento misure, dove previste.
7. Si eseguono i calcoli CCE per il processo richiesto.
8. Si scrivono output e tracking su tabelle/artefatti previsti.
9. Il job termina con log applicativo e stato esecuzione.

## 3. Modifiche da apportare ad ogni singola componente del progetto

### 3.1 `pom.xml`
1. Portare Spark 2.4 -> Spark 3.x (versione coerente col cluster target).
2. Portare Scala 2.11 -> 2.12 (o versione richiesta dalla distro Spark 3).
3. Aggiornare plugin build/test (scala-maven-plugin, surefire, eventuali compatibilità).
4. Verificare dipendenze transitive legacy e conflitti (`provided`, serializer, logging).

### 3.2 Codice Scala (`src/main/scala`)
1. Verificare tutte le query/DataFrame API rispetto a Spark 3 (ANSI, cast, null handling, parser datetime).
2. Ricontrollare join/aggregazioni e semantica di ordinamento/grouping.
3. Validare codice controller/DAO su lettura e scrittura Hive con Spark 3.
4. Verificare utility di parsing parametri e gestione errori in run distribuito.

### 3.3 Configurazioni (`src/main/resources`)
1. Riesaminare `application.conf` e profili (`prod/dev/coll`).
2. Validare proprietà SQL/runtime Spark (shuffle, overwrite dinamico, timeouts).
3. Verificare compatibilità logging (log4j e configurazione driver/executor).

### 3.4 Deploy (`src/main/resources/deploy`)
1. Aggiornare `run_cce.sh` a runtime Spark 3 del cluster (comando submit, conf compatibili).
2. Rivedere memory/cores/dynamic allocation in base a performance reali su Spark 3.
3. Verificare file distribuiti con `--files` e path config su HDFS/local.

## 4. Test da prevedere

### 4.1 Test unitari
1. Test parsing argomenti e validazioni.
2. Test unitari su controller principali (ammissibilità/annullamento/calcolo).
3. Test DAO con dataset ridotti e casi limite (null, duplicati, date anomale).

### 4.2 Test di integrazione
1. Esecuzione end-to-end su ambiente DEV con tabelle di test.
2. Test per ciascun processo CCE (P/PR/PEIN/PREIN).
3. Verifica scritture su tabelle finali e tracking.

### 4.3 Test di regressione
1. Confronto output Spark 2 vs Spark 3 su stesso periodo input.
2. Confronto KPI business (volumi, conteggi, importi/regole calcolo).
3. Verifica performance baseline (tempi, shuffle, skew).

### 4.4 Test operativi
1. Dry-run degli script di deploy.
2. Verifica logging, retry, gestione errori e restart.
3. Test parametrico su profili e varianti di carico.

## 5. Glossario minimo
- **CCE**: processo di calcolo business del dominio.
- **DAO**: componente di accesso ai dati.
- **Ammissibilità**: fase di validazione record eleggibili.
- **Spark 3 migration**: adeguamento runtime, API e semantica SQL.
